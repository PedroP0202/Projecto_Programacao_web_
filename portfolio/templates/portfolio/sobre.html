Sobre a Aplicação

Esta é uma aplicação desenvolvida com a framework Django, que serve como um portfólio digital, diário de bordo e blog para documentar o meu percurso académico e profissional.

Tecnologias Usadas

  • Backend: Python, Django, Django Ninja (REST API)
  • Frontend: HTML5, CSS3, JavaScript Vanilla
  • Base de Dados: Neon (PostgreSQL) em produção; SQLite para desenvolvimento local
  • Armazenamento (Media): Cloudinary
  • Integração Externa: biblioteca requests para consumo de APIs externas

Arquitetura da Solução & CI/CD

A aplicação está alojada de forma contínua através de um pipeline CI/CD (Continuous Integration / Continuous Deployment). O código está num repositório GitHub e qualquer alteração (commit) desencadeia um fluxo automatizado que:

  1. Testa a aplicação garantindo a ausência de erros (linting, testes unitários).
  2. Compila os assets estáticos utilizando o WhiteNoise para servir ficheiros eficazmente.
  3. Publica os novos ficheiros no servidor de produção de forma automática.

Os ficheiros multimédia ficam armazenados no serviço cloud Cloudinary. A base de dados principal encontra-se escalada no serviço gerido Neon, proporcionando escalabilidade horizontal e resiliência a perdas de dados.

🔑 API Key – Segurança da API

Esta aplicação expõe uma API RESTful (construída com Django Ninja) para gerir dados de ginásio: grupos musculares, planos de treino e exercícios.

Para proteger os endpoints de escrita (criação, edição e eliminação de dados), é utilizado um mecanismo de autenticação por API Key:

  • Cada chave de acesso é armazenada na base de dados como um objeto APIKey, com nome, estado ativo/inativo e data de validade.
  • A chave é gerada automaticamente de forma segura com secrets.token_urlsafe(32).
  • Quem faz pedidos à API deve incluir o header HTTP X-API-Key: <chave>.
  • O Django Ninja valida a chave em cada pedido: se não for válida ou tiver expirado, devolve 401 Unauthorized.
  • Os endpoints GET (leitura) são públicos; os de escrita são privados.

A documentação interativa (Swagger) da API está disponível em /api/docs.

🌐 Integração com APIs Externas – biblioteca requests

Para além de produzir a sua própria API, esta aplicação consome uma API externa de um colega — a Paintball Events API — utilizando a biblioteca Python requests.

O fluxo de integração funciona assim:

  1. A view Django chama requests.get(), requests.post(), requests.put() ou requests.delete() com o URL da API externa.
  2. A API Key do colega é incluída no header X-API-Key de cada pedido.
  3. A chave é lida de uma variável de ambiente (.env) e nunca está hardcoded no código-fonte.
  4. A resposta JSON é parseada e passada ao template Django para visualização.

Esta integração permite realizar as 5 operações CRUD (listar, ver, criar, editar, apagar) sobre eventos, participantes e equipas de paintball, diretamente a partir deste portfolio.
